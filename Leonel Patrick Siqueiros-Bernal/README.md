## Quick Start Guide
Linux Ubuntu 22.04 should be installed along with ROS2 Humble. The “ros2_ws” package should be downloaded.

### Setting up ROSbot 2 PRO:
Open a new terminal on the computer and ssh into the ROSbot. Please note that you must figure out the ROSbot’s IP to connect to it.

```ssh husarion@<IP>```

Password: husarion

Start the ROSbot and RPlidar docker containers:

```docker compose up -d rosbot rplidar```

The Astra camera docker container is not used within this project, but can be launched with:

```docker compose up -d astra```

Docker containers can be stopped when no longer needed with ```docker stop <service>```.

### Setting up and running algorithms:
Open a new terminal and navigate inside the “ros2_ws” directory. Input the following commands:

```
colcon build
source install/local_setup.bash
Source ROS2 Humble:
source /opt/ros/humble/setup.bash
```

One of three files should be launched based on need:

#### To launch just the SLAM algorithm:
```ros2 launch ros2_slam slam.launch.py```
#### To launch SLAM and nav2 algorithms:
```ros2 launch ros2_slam localization.launch.py```
### To launch SLAM, nav2, and exploration algorithms:
```ros2 launch ros2_slam explore.launch.py```
### To launch rviz:
```rviz2```

Once in rviz, open the configuration file in ros2_ws/ros2-slam/rviz/explore.rviz.

## Code And File Documentation
This section will be organized in sections based on their organization within the project’s file structure. This documentation does not aim to explain the code on a line-by-line basis but rather aims to provide the general purpose of the file as well as some notable aspects of the code that are useful for understanding said code.

### /m-explore-ros2
- A supplementary package taken from https://github.com/robo-friends/m-explore-ros2 that aids in determining which spots the ROSbot can navigate to that remain unexplored. The package takes in the map topic generated by the SLAM package and sends spots it has deemed as unexplored to the nav2 package. Also known internally as the explore-lite package. Further documentation can be found on the github page.

### /ros2-slam
#### /rviz
#### -- Explore.rviz
Contains a configuration file to be loaded into rviz that has SLAM map and costmap display as well as a nav2 interface set up. The explore_lite package can determine which location the robot will visit next, however target positions can be manually set by using the “nav2 goal” tool and the “Waypoint/Nav through poses mode” located on the sidebar.
#### /launch
#### -- slam.launch.py
Creates and launches the SLAM algorithm node.
#### -- localization.launch.py
Creates and launches the SLAM and nav2 algorithm nodes.
#### -- explore.launch.py
Creates and launches the SLAM, nav2, and exploration algorithm nodes.
#### -- pycache
An auto generated file created during the build process that does not have a direct purpose.
#### /config
Contains the configuration .yaml files for the SLAM, Nav2, and exploration packages.
#### -- Slam.yaml
Contains the parameters to be accessed by the SLAM package. Documentation on each parameter can be found at https://github.com/SteveMacenski/slam_toolbox.
#### -- Navigation.yaml
Contains the parameters to be accessed by the nav2 package. Documentation on each parameter can be found at https://automaticaddison.com/ros-2-navigation-tuning-guide-nav2/.
#### -- Explore.yaml
Contains the parameters to be accessed by the explore_lite package. The package takes in the  same structure and parameters as the nav2 package. Documentation on each parameter can be found at https://automaticaddison.com/ros-2-navigation-tuning-guide-nav2/.
#### /src
An auto generated file created during the build process that does not have a direct purpose.
#### /maps
An auto generated file created during the build process that does not have a direct purpose. Can be used to save and store maps generated by the SLAM algorithm.
#### /img_data
An auto generated file created during the build process that does not have a direct purpose. Can be used to save and process data collected from the ROSbot 2 PRO’s Astra camera.
#### /include
An auto generated file created during the build process that does not have a direct purpose.
#### CMakeLists.txt
A file used in the facilitation of building the package.
#### Package.xml
An auto generated file created during the build process that does not have a direct purpose.

## Limitations Encountered

#### Resolved Limitations
- The latest nav2 package supported by ROS2 Foxy was too outdated to be viable for use within the project. Because of this, a switch was made towards using ROS2 Humble along with the Ubuntu 22.04 operating system.

- The docker containers utilized within the ROSbots were outdated and lacked key features, such as the ability to create and assign namespaces. The manufacturer, Husarion, was contacted regarding the matter in order to update the software with the newest possible versions of the docker containers and firmware as well as to fix some unintended behavior within their code.
- - https://community.husarion.com/t/rosbot-2-pro-rplidar-doesnt-work-root-operation-not-permitted/1994
- - https://community.husarion.com/t/rplidar-add-namespace/2012
- - https://community.husarion.com/t/rosbot-2-pro-updating-rosbot-docker-gives-root-operation-not-permitted/2017/8 

#### Ongoing Limitations
- There is a fundamental flaw in the ROSbots which renders them incapable of separating and distinguishing data through the use of namespaces. This is an issue caused by the decision to use the microros package as a bridge between the hardware and software of the robots. This issue has been brought up to Husarion. They have responded that they will not be fixing this issue because they are not the ones who wrote the microros package.
- - https://community.husarion.com/t/rosbot-2-pro-issue-with-rosbot-docker-container-namespaces/2031 
- Without the way to effectively distinguish what data is from and is sent to the ROSbots (Such as through namespaces), this project cannot handle multiple robots at the same time. The namespaces allows for the Ubuntu machine to be able to determine what lidar data is sent from which ROSbot. However, due to the aforementioned issue with microros, the rosbots are unable to distinguish what navigation messages are meant for them despite using namespaces.
- - https://github.com/micro-ROS/micro-ROS-Agent/issues/126 
- The VPN service provided by Husarion for their robots allows for lidar data and navigation messages to be separated by ensuring that everything is stored and processed locally by each ROSbot. The only thing that is sent over the network are snapshots of the maps generated by each robot. This approach is unfeasible because both the SLAM and navigation algorithms are done by the robots themselves, defeating the purpose of creating an edge architecture. Additionally, since only snapshots of the generated maps are sent rather than the actual /map topics generated by the SLAM algorithm, map merging cannot be done using this approach.

## Future Recommendations
Due to the issue stemming from microros, the current approach of using namespaces for handling multiple robots over a network cannot cannot be done. Unless Husarion switches the middleware package used or the microros team decides to fix this issue, either a new approach must be devised or the robots used must be switched out.
